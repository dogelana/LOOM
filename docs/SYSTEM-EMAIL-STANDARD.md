# LOOM System Email Standard

LOOM system email is a global engine service for **permanent accounts**. It is intentionally separate from project-specific messaging. Configuration and delivery history live only in the protected Instance Vault under `instance/data/email/`; release packages never ship or replace those credentials.

## Supported delivery transports

LOOM supports two host-agnostic outbound delivery modes:

1. **SMTP (recommended)** — configurable host, port, STARTTLS / implicit SSL-TLS / no encryption, optional authentication, username, password, and timeout.
2. **PHP mail()** — provided only for hosting environments that explicitly configure and support PHP's native mail transport.

The Admin Email tab never returns a saved SMTP password to the browser. Leaving the password field blank preserves the currently saved credential.

## Setup flow

Open **LOOM Admin → Email** and configure the sender identity first. The public base URL is optional; when blank, LOOM derives the current installation URL from the request host and LOOM web path.

For SMTP, enter the exact connection values supplied by the email host. Then:

1. Save Email Settings.
2. Run **Check Connection**. SMTP checks connect, negotiate encryption, and authenticate without sending a message.
3. Send a test email to an address you can inspect.
4. Enable system delivery when the checks are healthy.
5. Configure SPF, DKIM, and DMARC in domain DNS using records supplied by the email provider. LOOM does not invent provider-specific DNS records.

A successful SMTP or PHP transport response means the message was accepted by the configured transport. Inbox placement remains controlled by the receiving provider, DNS reputation, spam policy, and sender-domain configuration.

## Starter notification suite

Each email category can be enabled or disabled globally and has an editable subject line:

- Welcome to LOOM — after a guest becomes a permanent account.
- Password reset — one-time 30-minute recovery link.
- Password changed — security notice after any password replacement.
- Email changed — confirms a permanent account email update.
- Referral attributed — tells a permanent referrer when a person is attributed to a reusable referral link.
- New sign-in — optional security notice; off by default to avoid excessive mail.
- System test — Admin-only diagnostic delivery.

Core HTML/text bodies are generated by LOOM so password-recovery security language and action URLs remain consistent. The global footer and subjects remain configurable.

## Forgot-password security

`forgot-password.php` deliberately returns the same public response for registered and unregistered addresses. This avoids account enumeration. Requests are rate-limited by one-way hashes of the normalized email and observed network address. Reset tokens are random, stored only as SHA-256 hashes, expire after 30 minutes, and are one-time use.

A successful reset replaces the password using PHP `password_hash()`, revokes all existing login sessions for that account, invalidates all outstanding reset tokens for the same account, and may send a Password Changed notice.

Email recovery restores a permanent account credential only. It does not merge unrelated guests or bypass LOOM Continuity Cluster / authentication authority rules.

## Persistence and privacy

SMTP credentials, reset-token hashes, rate-limit metadata, and delivery logs are Instance state. Delivery logs contain masked recipient addresses and transport results rather than message bodies or passwords. Email delivery failure never rolls back successful account creation, referral attribution, or password replacement.
