# LOOM Cache-Busting Standard

LOOM treats stale client assets as an engine concern, not a project-specific workaround.

## Rules

1. API JSON responses use `Cache-Control: no-store`.
2. Module discovery responses are fetched with `cache: no-store` and a request nonce.
3. Dynamically imported module JavaScript uses the module content fingerprint as `?v=`.
4. Module CSS uses the same module fingerprint as `?v=`.
5. `resolveAssetPath()` returns an asset URL containing a content-hash `?v=` generated by the server. Replacing an image while keeping the same filename therefore produces a new browser URL automatically.
6. LOOM-owned static engine scripts, Pegboard CSS/JS, Registry scripts, and active project bootstrap scripts include the current engine version in their URLs.
7. Project app links emitted by the project registry contain a content version of that project's `app/index.html`.
8. The packaged Apache `.htaccess` disables static caching as an additional development/deployment safeguard. Query-string versioning remains the primary portable mechanism and works with the PHP development server as well.

## Module Author Rule

Project modules should resolve project assets through `ctx.resolveAssetPath(path)` instead of constructing project asset URLs manually. The returned URL is already cache-busted by content.

If a module must construct a URL itself, it may use `ctx.cacheBustUrl(url, version)`.
